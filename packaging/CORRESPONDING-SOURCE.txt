Qt/PySide 6.11.1: replace ABI-compatible DLLs, Python extension modules, plugins,
resources and QtWebEngineProcess together under _internal/PySide6 and shiboken6.
Qt WebEngine's Chromium/FFmpeg and Qt PDF/PDFium sources are included in the
qtwebengine-everywhere-src-6.11.1 source archive. The other Qt module archives and
pyside-setup archive contain their upstream build scripts and instructions.
Windows builds require a supported MSVC toolchain, CMake/Ninja and the additional
WebEngine build prerequisites described in that exact source tree. Alternatively
rebuild compatible PySide wheels, install them in an isolated build environment,
and rebuild this application using scripts/build_windows_portable.ps1.

IfcOpenShell: upstream revision 1c5b825d8ef05ab9d14a15dac12e9eae2f5a37c2,
WITH_CGAL=OFF and WITH_OPENCASCADE=ON; all eight IFC schemas are retained.
The Windows wheel is a local 0.8.5+nocgal.1 build, not the unmodified PyPI binary.
OCCT 7.8.1, revision bd2a789f15235755ce4d1a3b07379a2e062fdc2e, is built as shared
libraries. Replace the extension, regenerated SWIG wrapper and its OCCT DLLs
together under _internal/ifcopenshell. The dedicated native-ifc.yml workflow and
scripts/build_ifcopenshell_no_cgal.ps1 / assemble_no_cgal_wheel.py record the build.
The upstream interface has a minimal patch moving shared OpaqueCoordinate SWIG
declarations outside the CGAL guard. The complete ifc-swig.patch is supplied in
licenses/python-package-metadata/ifcopenshell-0.8.5+nocgal.1.dist-info; apply it
to the supplied upstream tree, or use scripts/apply_ifc_swig_fix.py. Its digest
is recorded in NO-CGAL-BUILD.json. No native geometry algorithm is changed.

The build receipt records exact inputs/configuration and DLL imports. Optional
CGAL, IFCXML, HDF5, COLLADA, upstream glTF/USD/RocksDB backends are not built;
the product's own GLB generation, STEP IFC comparison and OpenCASCADE mesh path
are retained and must pass regression tests. This does not add support claims.

GEOS 3.13.1: LGPL-2.1-or-later; source archive and upstream build instructions are
included. Compatible GEOS libraries can be replaced under _internal/shapely.libs;
rebuilding the Shapely 2.1.2 wheel and application is another supported route.
Python, NumPy, other Python packages, Rust crate dependencies and build-tool
sources/notices are identified in the inventory. The source collection includes
some development-only components; their presence in a source archive does not
mean their binaries are included in the application.

Library substitution changes the tested software and may affect correctness or
stability. Run the offline unit/research and frozen 3D checks on your rebuilt
application. No warranty is supplied; see the individual licenses.
