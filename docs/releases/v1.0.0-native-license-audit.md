## IfcOpenShell / 几何依赖

The bundled Windows wheel identifies itself as `0.8.5-1c5b825`, resolving to
[commit 1c5b825d8ef05ab9d14a15dac12e9eae2f5a37c2](https://github.com/IfcOpenShell/IfcOpenShell/commit/1c5b825d8ef05ab9d14a15dac12e9eae2f5a37c2).
An explicit `ifcopenshell.geom.create_shape(..., geometry_library="cgal")` call
on the public synthetic source column succeeded and returned 44 triangles.
Thus CGAL is compiled in; selecting OpenCASCADE in the product does not remove
that code from the distributed binary.

The upstream [build definition](https://github.com/IfcOpenShell/IfcOpenShell/blob/1c5b825d8ef05ab9d14a15dac12e9eae2f5a37c2/cmake/CMakeLists.txt)
enables CGAL by default. The same revision's Windows dependency script selects
CGAL 5.5.5, whose [Nef polyhedron header](https://github.com/CGAL/cgal/blob/v5.5.5/Nef_3/include/CGAL/Nef_polyhedron_3.h)
declares GPL-3.0-or-later OR commercial licensing. The
[CGAL publisher](https://www.cgal.org/license.html) explains the GPL distribution
requirements; the [IfcOpenShell maintainers' discussion](https://github.com/IfcOpenShell/IfcOpenShell/issues/2977)
also distinguishes OpenCASCADE-only LGPL builds from CGAL-enabled builds.
This is a concrete redistribution review issue, not a claim that MIT source
and GPL code are inherently incompatible or that the application was relicensed.

当前 wheel 的 CGAL 内核实际可运行，不能以产品默认调用 OpenCASCADE 为由忽略其
GPL 分发要求。项目源码仍为 MIT，没有擅自变更许可。

Recommended MIT-preserving route: build the same IfcOpenShell revision with
`WITH_CGAL=OFF`, preserving the product-used OpenCASCADE capabilities and schema
coverage; assemble all remaining native notices/corresponding source, then
repeat source, frozen-geometry and isolated installer/upgrade/uninstall checks.
This would be a new native dependency artifact, not a verified drop-in replacement
yet. An alternative GPL-compliant combined distribution requires an explicit
maintainer licensing decision; no commercial license is assumed.

建议保持 MIT，按同一修订重编不含 CGAL 的依赖，保留产品所用 OpenCASCADE 与 schema
范围，并重新完成几何及安装验收。这是新的原生依赖构建，不能沿用现有二进制的
验收结论。若改走 GPL 组合分发，必须由作者明确决定，不能由发布脚本自动处理。
